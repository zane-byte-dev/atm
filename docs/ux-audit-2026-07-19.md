## 1. 结论摘要

ATM 已经具备可长期日常使用的主体框架：任务状态清楚、等待依赖可追踪、知识能浏览和检索、用量与 Skill 统计有实际数据、CLI 响应非常快。过去几轮修复后，任务默认选择、已完成任务折叠、空状态、错误文案、冷启动本地优先等基础体验明显成熟。

本轮不建议继续平均打磨各页面，而应先解决“结果可信度”问题。最重要的发现是：

1. **全局搜索在同一浮层内连续修改查询时，会复用旧行内容，甚至出现类别串位。** 例如先搜索 `ATM`，再缩小为 `ATM 持续优化`，界面曾显示旧的 T60/T64；另一轮宽泛搜索中，“任务”分组第二行直接显示了 Codex 会话。CLI 返回的实际结果是 T80 和会话 `67c8e4a2`，说明数据层正确，问题在 SwiftUI 结果行身份复用。
2. **30 天图表日期仍不可读。** 虽然已经减少刻度，但实际界面中的标签仍被压成 `6/...`、`7/...`，总量和按模型视图都存在。
3. **Agent 页与当前绑定状态的产品语义不一致。** `atm session current` 明确显示当前 Codex 会话绑定 T80，但 Agent 页显示“Agent 0 / 当前没有活跃 Agent”。从实现角度两者可能使用不同信号，从用户角度却像数据丢失。
4. **知识治理有结构、没有反馈飞轮。** 当前 93 篇知识全部健康，但质量汇总中的 retrieval / adopted / corrected / rejected 全为 0。用户可以看到治理面板，却无法从中判断哪些知识真的被使用、采纳或纠正。

建议下一轮只做“可信度修复包”：先修搜索结果身份，再修 30 天日期，再统一 Agent 状态定义。完成后再进入知识反馈闭环和可靠性增强。

## 6. 详细问题与修复方案

### P0-1 全局搜索结果身份错误

#### 现象

在同一个搜索浮层中：

1. 输入 `ATM`，得到大量任务和会话；
2. 再输入 `ATM 持续优化`；
3. CLI 正确结果为 T80 和 Codex 会话 `67c8e4a2`；
4. UI 曾继续显示旧的 T60/T64；
5. 另一轮从精确查询切回 `ATM ` 后，“任务 13”分组的第二行显示了 `Codex · atm` 会话内容。

这不是模糊排序问题，而是内容与类别发生了串位。

#### 根因

`DesktopSearchPalette.swift` 的四类结果各自通过真实模型 ID 进入 `ForEach`，但每一行随后又使用全局序号 `.id(index)`。查询变化后，0、1、2 等序号会被新结果复用，SwiftUI 因此保留旧行的内容和视图状态。跨类别的全局序号变化还会让旧会话行进入新的任务位置。

#### 建议方案

- 结果行使用稳定、带类别前缀的身份：
  - `task:<todo.id>`
  - `session:<session.shortID>`
  - `knowledge:<documentID>`
  - `memory:<memory.id>`
- 键盘滚动不要依赖行的 SwiftUI identity；单独为每个结果生成 `scrollAnchorID`。
- 将四类结果先映射为统一的 `SearchResultItem`，其中包含：
  - 稳定 ID
  - 类型
  - 标题/摘要/标签
  - 打开动作所需的领域对象
- 增加“快速连续输入”测试，覆盖旧请求取消、结果收缩、类别数量变化和相同索引复用。

#### 验收标准

- 从 `ATM` 缩小到 `ATM 持续优化`，只显示 T80 和实际命中的会话。
- 从精确查询放宽到 `ATM`，任务分组中不能出现会话、知识或记忆行。
- 连续输入 20 次不同查询，最终内容必须与同一时刻的 CLI JSON 一致。
- 上下键选择和滚动仍正常，回车打开的对象与当前可见行完全一致。
- 旧请求晚返回时不得覆盖新查询结果。

### P1-1 30 天日期标签仍被截断

#### 现象

30 天总量柱状图和按模型折线图的横轴均显示为 `6/...`、`7/...`。减少刻度数量后，Swift Charts 仍在类别轴上分配了过窄的标签空间。

#### 建议方案

优先使用真正的日期连续轴，而不是已经格式化的字符串类别轴：

- X 值传入 `Date`；
- `AxisMarks(values: .stride(by: .day, count: 5))`；
- 首日、月初、末日按需要补充；
- `AxisValueLabel(format: .dateTime.month().day())`；
- 标签可设置居中或锚点，避免首尾被裁切。

如果短期继续使用字符串轴，应至少：

- 只保留 5–6 个刻度；
- 为 label 设置固定最小宽度；
- 禁止文本截断，允许标签越过单个类别带宽；
- 保证首尾刻度完整。

#### 验收标准

- 标准 1000×720 窗口下，30 天总量和按模型视图均能读出完整 `6/20`、`6/25`、`6/30`、`7/5`、`7/10`、`7/15`、`7/19`。
- 首日和末日不被裁切。
- 7 天和今日视图不回退。
- VoiceOver 仍能读取完整 ISO 日期与数值。

### P1-2 Agent 页与当前会话状态不一致

#### 现象

- `atm session current --json`：当前 Codex 会话绑定 T80。
- `atm session status --json`：`sessions: []`。
- macOS Agent 页：`Agent 0`，并提示“当前没有活跃 Agent”。

这在实现上可能是“绑定会话”和“有实时心跳的 Agent”两套定义，但界面没有解释。用户刚在 Codex 中使用 ATM，却看到 Agent 0，会自然判断 ATM 没有统计当前 Agent。

#### 建议方案

选择并明确一种产品定义：

1. 推荐：Agent 页同时展示两个层次。
   - “正在运行”：有实时工具/心跳活动的 Agent；
   - “当前绑定”：已通过 ATM session binding 关联到任务的会话。
2. 如果只保留实时状态：
   - 空状态改为“暂未检测到实时活动”；
   - 同时展示最近绑定会话，避免“0 = 完全没记录”的误解。
3. 在 CLI 中明确 `session status` 与 `session current` 的差别。

#### 验收标准

- 当前 Codex 会话绑定 T80 时，Agent 页至少能看到该绑定。
- 没有心跳时不得用“没有 Agent”概括全部状态。
- 用户能在 5 秒内回答“哪个 Agent 正在做哪个任务、最后一次活动是什么时候”。

### P1-3 知识质量反馈飞轮没有数据

#### 现象

- 93 篇知识，结构审计 0 问题；
- quality 汇总：retrievals=0、adopted=0、corrected=0、rejected=0；
- 本轮实际使用了知识搜索和知识浏览，但没有形成反馈记录。

当前面板只能证明“文档格式健康”，不能证明“知识帮助了工作”。

#### 建议方案

- 搜索结果被打开时记录 retrieval，而不是仅在搜索返回时记录；
- Agent 通过 ATM 工具引用知识时记录 machine retrieval；
- 提供低摩擦反馈：
  - 采用
  - 有帮助但需补充
  - 已纠正
  - 不相关
- 如果 Agent 最终答案引用了知识，可自动提议 adopted，由用户或后续行为确认；
- 质量面板展示：
  - 最近 30 天被使用最多的知识
  - 从未命中的知识
  - 高纠正率知识
  - 搜索无结果的高频关键词

#### 验收标准

- 从 macOS 或 CLI 打开知识搜索结果后，retrieval 增加 1。
- 用户反馈能关联到具体知识、查询和会话。
- 质量页能区分“结构健康”和“使用有效”。
- 一周真实使用后四个质量指标不再全部为 0。

### P1-4 macOS 命令执行没有超时和取消

#### 现象

`ATMCommandRunner.run` 使用 `Process.waitUntilExit()`，同时正确并发排空 stdout/stderr，但没有：

- 超时；
- Task 取消后终止子进程；
- 读取命令与同步命令的不同时间预算；
- 卡住后的重试入口。

正常路径很快，但一旦 CLI 等待锁、损坏数据源或外部命令卡住，页面可能一直显示加载中。

#### 建议方案

- 只读查询默认 15 秒；
- `sync` 默认 120 秒；
- 明确的长任务单独配置或不设默认超时；
- Task 取消时先 `terminate()`，宽限后再强制结束；
- 错误中区分超时、取消和 CLI 非零退出；
- 页面展示“重试”，同步按钮恢复可点。

#### 验收标准

- 注入一个永不退出的测试进程，15 秒后界面恢复并显示可理解错误。
- 关闭搜索浮层时，未完成搜索进程被取消。
- stdout/stderr 大输出回归测试继续通过。
- 正常 0.07–0.38 秒路径没有明显性能回退。

### P1-5 数据健康仍有 5 个未闭环项

`atm doctor` 当前报告：

1. Claude 数据源缺失但保留旧索引；
2. Codex request coverage 95.1%；
3. Codex 有 39 个 unknown-model request events；
4. Pi 详细计数 6470，比上游汇总 6453 多 17；
5. Qoder request coverage 0.0%。

这些不会阻断日常使用，但会影响模型成本、请求级统计和数据“完全可信”的表达。

建议在用量页增加轻量数据健康入口，并把估算费用明确标为“基于当前覆盖率”。Doctor 的每项问题应给出影响范围、修复命令或“上游暂不提供”的明确结论。

### P2-1 任务详情被历史动态淹没

T65 的等待原因和依赖是可见的，但后面紧接大量历史动态。对“恢复工作”而言，用户最想知道的是：

1. 为什么等；
2. 等谁；
3. 解除等待后做什么；
4. 最近一次变化。

建议将这些信息做成详情顶部的固定状态卡，历史动态默认只展示最近 3 条，其余折叠为“查看全部 25 条”。

### P2-2 `todo resume --help` 信息不足

当前帮助只有：

> Resume working on a todo by continuing its last session

没有说明：

- 如何选择“last session”；
- 没有绑定会话时会发生什么；
- 支持哪些 Agent；
- 是否会切换当前 session binding；
- JSON 输出和退出码。

建议补充 2–3 个示例和失败条件。此命令直接影响跨会话恢复，是 ATM 核心价值的一部分，不应只有一句说明。

### P2-3 Schedule 空状态缺少上手入口

`No schedules configured.` 是正确空状态，但用户仍不知道如何创建第一个定时任务。建议附一行最小示例或 `Run "atm schedule add --help" to create one.`。

### P2-4 `swift run` 的开发能力边界

`swift run --package-path app/macos` 非常适合日常快速开发，但裸可执行文件不是完整 App Bundle：

- LaunchServices 和辅助功能难以按应用路径定位；
- Debug 通知需要安全降级；
- 图标、Bundle metadata、首次权限行为与正式包不完全等价。

建议保留现有命令，同时补一个可选的 `make dev-app` 或 `Scripts/run-dev-app.sh`：

1. SwiftPM Debug 构建；
2. 生成临时 `.app` 包；
3. 使用开发 bundle ID；
4. ad-hoc 签名；
5. 启动并保留终端日志。

这不是替换 `swift run`，而是给需要 UI 自动化、通知和权限验证的开发轮次使用。

## 9. 发布判断

### 当前适用范围

ATM 当前适合：

- 作者本人日常使用；
- 熟悉 CLI 与数据边界的内部用户；
- 早期试用和快速迭代。

### 暂不建议扩大分发的原因

不是因为功能不足，而是全局搜索存在“显示对象可能不是当前结果”的可信度缺陷。全局搜索是跨任务、会话、知识和记忆的统一入口，一旦结果身份不可靠，会放大到整个产品。

### 建议发布门槛

正式扩大分发前至少满足：

1. P0 搜索问题修复并有竞态/身份回归测试；
2. 30 天日期完整可读；
3. Agent 空状态语义明确；
4. `atm doctor` 的 5 个问题至少被解释，不一定全部能修复；
5. 完成一次干净环境安装与升级验证。
