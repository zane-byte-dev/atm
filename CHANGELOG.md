# Changelog

What changed between releases, grouped by what it means for someone using ATM.

This file is written by hand and covers user-visible change only. The GitHub
release notes are generated by goreleaser from the commits in each tag, so they
are the literal list; this is the readable one. The two do not overlap exactly:
goreleaser filters out `docs:`, `test:` and `chore:` commits, while this file
keeps the decisions among them — a design decision that closes off a feature
answers a question users ask, even though no code changed.

ATM is a single-user tool with one live database, so upgrades never carry a
migration you have to run — but they also never carry backward compatibility for
a database from a much older version. `atm backup` exists for exactly that case.

## [0.2.0] — unreleased

### Added

- **`atm backup` and `atm restore`.** Todos, memory, knowledge, the collection
  ledger and the review cursor are this database's own records; nothing else
  holds a copy. The archive carries them plus the plain-file records under
  `~/.atm`, and leaves the session mirror out because `atm sync` rebuilds it —
  which keeps the archive an order of magnitude smaller than the database.
  It works on a database too old for the current build to open, so it is also
  the escape hatch when a schema is rejected as unupgradable.
- **`atm diagnose`, with `--bundle`.** Writes one file holding the versions,
  both schema versions, doctor's findings, data source presence, the last sync
  error and the tail of the CLI and App logs — enough to answer most of what a
  first reply to a bug report would ask for. Paths under `$HOME` are rewritten
  to `~`, directories are reported by count and size rather than by file name,
  and no session text, record content or credentials are collected. It reads
  local state only and uploads nothing.
- **Failures are written to disk** at `~/.atm/logs` (`cli.log`, `app.log`), one
  JSON object per line, capped at 5 MB with one rotation kept. Only failures and
  process boundaries are recorded — never content, and never command arguments,
  since `atm todo add "<title>"` carries exactly what must not be logged. The
  App records whether the previous run exited cleanly, which is the only way a
  crash is visible at all.
- **`atm doctor` reports extraction, not just discovery.** Indexed sessions with
  no messages behind them, or an agent with no token accounting where its parser
  claims to provide it, are now surfaced as warnings pointing at a likely
  upstream format change. Agents whose upstream never reported tokens (Copilot)
  are excluded, so the check does not fire on a documented limitation.
- **Collection sources can be watched per message** rather than per time window,
  which stops a notification feed from collapsing a batch of unrelated events
  into a single decision. Bot sources are supported and shown with their own
  glyph.

### Changed

- **A locally built binary reports the commit it came from.** `make install`
  previously stamped a hardcoded `0.6.0` into every build regardless of the
  source, and a build without linker flags claimed the same version. The version
  now comes from `git describe`, and the no-flags fallback is `dev`.
- **The unupgradable-schema message points at `atm backup` first.** It used to
  say to delete the database and re-sync, which rebuilds the session mirror and
  destroys every record that has nowhere to rebuild from.

### Fixed

- **A dashboard contract mismatch says which side to upgrade.** It surfaced as
  `Unsupported ATM dashboard schema 7` wrapped in a "some data did not refresh"
  prefix — accurate, and no help. Each direction now gets its own instruction,
  both versions are named, and it is no longer presented as a partial refresh
  when nothing refreshed at all.
- **A quota card stays visible when its reading goes missing.** A daily quota is
  only observed while its page is open, so every morning the card left the grid
  entirely — an absent card reads as "this quota is gone" when the truth is
  "this reading is missing". Cards are now held as metric-less placeholders for
  up to seven days.
- **The collection classifier accepts a fallback chain.** One rate-limited
  account used to stop collection for every source with no way to switch agents
  short of a code change.

### Decided

Recorded in [DESIGN.md](DESIGN.md) so they stop being reopened. Listed here
because each one answers a question users ask:

- **Team and multi-machine sharing are not a product goal.** ATM serves one
  person on one machine. Cross-machine use goes through `atm backup` and
  `atm restore` — a deliberate move, not background sync.
- **The session mirror is never cleaned automatically.** No retention window, no
  background compaction; the index only grows. Outliving the agents' own logs is
  the point of it. `atm session forget` remains the only deletion path.
- **Knowledge is still read in full on every search**, with a stated trigger for
  revisiting that: past 500 documents, or once a search reliably exceeds 300 ms.

## [0.1.1] — 2026-08-04

### Fixed

- **The installer no longer depends on an anonymous GitHub API call**, which was
  rate-limited to a 403 for some users, and verifies the SHA-256 checksum of what
  it downloads.
- **Concurrent database opens no longer contend for the write lock** when the
  schema is already current, which could exhaust SQLite's busy window and fail
  unrelated short-lived commands.

## [0.1.0] — 2026-08-04

First public release.

### Added

- **Extensible quota providers** via a versioned command protocol, so a private
  or third-party quota source can be added without changing ATM.

Everything else in this release is ATM's existing feature set — session
indexing across eight agents, work state, shared memory, central knowledge,
usage and cost accounting, the macOS menu bar app — made publishable: license,
third-party notices, privacy and security policy, contribution guide, release
pipeline and installer.
