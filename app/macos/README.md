# ATM for macOS

ATM 的原生 macOS 桌面应用。主窗口提供任务搜索与筛选、Markdown 详情、编辑、
外部需求收集、
Agent 活跃监视器、知识工作台，以及配额与 Token/会话用量分析。用量页顶部“额度”按 Agent 展示
可用的速率限制窗口、已用百分比和重置时间。知识工作台从左侧“知识”展开具体
知识库，中栏浏览文章，右栏查看完整内容；共享记忆作为特殊知识库呈现。工作台支持
新建与导入 Markdown、编辑信息、右键移动到其他知识库、可恢复归档及二次确认永久删除。跨任务、
会话、知识与共享记忆的搜索统一由 `⌘K` 搜索面板提供，知识库列表本身不带库内检索。详情页支持 Markdown
编辑/预览和 `⌘S` 保存；文件导入条目会回写源文件并重新导入，共享记忆
会创建保留历史的新版本。Agent 页按“需要你、正在活跃、刚刚活跃”展示近期观察到的各个 Agent 会话，
点击卡片后在右侧显示详情，再由“打开来源”回到来源会话：Codex Desktop 使用完整 thread id 的 `codex://threads/…`
深链，Terminal/iTerm 使用进程 TTY 选择对应标签页，IDE 在缺少会话级标识时打开对应项目窗口。
Codex 会话标题直接读取其 thread index，与 Codex Desktop 中显示的标题保持一致；卡片和详情同时保留
最近一次用户输入，长回合中也会从轻量 `user_message` 事件反向定位，不受工具日志数量影响。首次定位 Terminal/iTerm
时 macOS 可能会请求“自动化”权限。默认开启的“刘海 Agent”会把活跃及最近 30 分钟的会话保留在屏幕顶部：
物理刘海屏以相机区域为中心显示两侧状态，无刘海屏降级为顶部居中的紧凑悬浮条。交互沿用 Ping Island
的原因分层：悬停后用一次连续的窗口动画直接展开到完整会话列表的最终尺寸，不叠加内容层的第二段动画；
悬停判定不走 SwiftUI 的 `.onHover`（tracking area 会在窗口变大时报一次假的移出，导致展开与收起来回翻转），
而是按光标真实位置判断，并且开合到点后都会重新读一次光标位置复核：停留 180ms 才展开、离开 220ms 才收起，
光标确实还在面板内时一律不收。紧凑态的触发区比画出来的条窄 20pt，避免伸手去点菜单栏图标时顺带把它拖开；
展开后改用完整面板范围，边缘不再是悬崖。展开态沿用 Ping Island 的浮岛信息架构：顶部只保留
Agent 配额、提示音与设置，下面用独立圆角卡片并排展示项目、当前任务、最近一轮对话、时间、Agent 和来源，
不再叠一层“会话列表”导航栏。每张卡显式标注“工作中 / 已完成 / 需要你 / 最近”；完成后的新输入会把
会话重新切回“工作中”，而“需要你”始终优先。点击紧凑态会固定同一个列表；点击外部后收起；点击会话直接回到来源。
绿色表示活跃、灰色表示最近，需要介入的新状态使用独立
通知态短暂展开；Agent 产生新的完整结果时也会短暂展开绿色完成卡，只显示会话标题和一行结果摘要，
点击直接回到来源。同一结果只提醒一次，App 启动时不会补播历史完成项，会话短暂离线再出现也不会重播；
“需要你”提醒优先于完成提醒。没有活跃或最近会话时自动隐藏。设置 → 刘海可开关，并沿用 Ping Island
的自定义能力再提供四项：显示屏（自动 / 主屏 / 指定某块外接屏，指定屏拔掉后自动回退到“自动”）、
无刘海屏位置（顶部居中 / 靠左 / 靠右，物理刘海屏始终居中对齐相机区域）、最近会话保留（15 / 30 / 60 分钟
或一直保留，“需要你”不受此限）、通知停留（4 / 8 / 15 秒或手动收起）。
同一页的“Agent 提示音”按“开始处理、需要介入、处理完成”分别选择声音并支持预听和音量；默认采用
Ping Island 的 `Menu Select`、`Approval Alert`、`Submit Blip` 三段 8-bit 音效，同时保留 macOS 系统音选项。
默认只开启需要介入与处理完成。声音由状态转移触发并按结果去重，不会随 3 秒轮询重复播放。
同一页的“Agent 事件推送”把感知层从扫会话记录换成 hook 推送：装上后 Agent 卡在授权或等你输入的那一刻
会经 `~/.atm/notch.sock` 直接推给刘海，刘海显示的是 Agent 报上来的原因（等待授权、等待输入）和被卡住的
工具名，而不是从最后一句回复里猜的。扫记录看不到工具授权——那一刻 Agent 不写任何文字——所以这不只是
更快，是原本完全漏掉的信号。装的都是只上报的 hook，不会拦住工具调用；App 没在跑时 hook 立刻静默退出。
已接 hook 的会话由事件驱动播放提示音并即时刷新，轮询退到 8 秒兜底；没接 hook 的 Agent 行为不变。
刘海或 Agent 工作区可见时会独立每 3 秒刷新一次
轻量会话状态，避免受主面板 60 秒刷新周期影响；较慢的主面板响应不会覆盖更新的实时状态。详情页只保留
当前输入、最新完成结果、最近三条执行动态、存在时的关联任务，以及折叠的技术信息；没有实时活动的 Session binding 不计入
活跃 Agent，Codex Desktop 内部的 auto-review helper 也不会伪装成用户可返回的活跃会话。菜单栏快速面板
只保留工作中、等待中、需处理项、活跃 Agent 和常用操作。临时记一条任务有三个入口：面板底部的
“添加任务”、面板打开时的 `⌘N`、以及状态栏图标右键菜单（面板没展开时也能用）。三者都激活主窗口
并弹出同一张输入卡——300pt 的面板放不下项目/优先级/领域三个 chip，维护两套 composer 只会让它们
逐渐不一致，所以菜单栏只提供入口，不复制输入界面。提交后弹窗收起并选中新建的任务。
任务详情和任务行右键都能“复制启动
提示”，把一行指针放进剪贴板；粘贴进新的 Codex 会话后 AI 会自己去读任务文档。完成任务后会
发送 macOS 原生通知，点击通知可打开主窗口。
任务详情的“Agent Sessions”页签把每个绑定会话按主题列出，而不是只列 id：标题由 CLI 决定——先用
Agent 自己写进索引的会话标题，Codex 不写标题就读它的 thread index，都没有才退回该会话第一句真正
由人打出来的提问（插件清单、AGENTS.md 之类的注入前言会被跳过）。行内还给出绑定时间、会话历时、
提问与工具调用次数、花费和工作目录；点行弹出完整对话（`atm session show`），行尾的按钮回到来源
会话——会话还活着就精确聚焦它的终端，已经结束的 Codex 线程用 `codex://threads/…` 深链重新打开，
其余已结束会话不显示按钮，只能看记录。

“收集”工作区采用来源、处理记录、详情三栏布局。设置中的“连接器”页可启停自动收集、调整频率并管理
外部来源。添加来源时填写 `collection_connectors` 中配置的连接器、来源类型和稳定 ID；连接器支持发现能力时，弹窗可调用 `atm collect source search` 列出候选。来源右键“查看消息记录”、
或处理记录详情“来源”卡片里的同名入口，会读最近 50 条聊天原文，用来补齐 `raw_context` 之外的上下文。
来源可选择高频“任务提取”或低频“只沉淀知识”；后者在配置层被限制为只能沉淀或忽略，永不创建 Todo，
模型判成建任务也会被降级成沉淀。沉淀的内容按来源每天汇总成一篇知识文档，落到来源上配置的知识库集合。
弹窗分两段：先 `atm collect history --local` 从本地已同步的记录读取，再调用连接器替换成最新内容并同步进本地库（默认保留 90 天，`atm collect search` 可检索）；
读取中副标题写“正在读取最新…”，连接器不可用时转成橙色说明这批是本地记录，而不是当成最新状态。App 常驻期间即使主窗口关闭，也会定时调用 `atm collect run` 和 `atm collect digest --due`；
新建和失败会汇总成原生通知（纯沉淀不打扰人，它没有任何待办）。处理记录支持查看原始聊天、打开 Todo、重新处理、转成 Todo、修正元数据和保留审计的撤销；历史补充记录仍可查看和撤销。

列表行与导航行的选中/悬停表面统一由 [`ATMListRow.swift`](Sources/ATMMenuBarApp/ATMListRow.swift)
的 `atmRowSurface` 提供，行内容仍归各自的视图。规则是**只填充，不描边、也不在选中时切字重**：
两者都会让行内文字重排——描边挤掉一圈可用宽度，字重切换改变字形宽度——点一下行标题就会左右抖一下。
同一原语分三档：中栏内容行（任务 / Agent / 知识 / 收集记录 / ⌘K 搜索结果，圆角 8、accent 11%）、
导航行（侧栏分区、收集来源，圆角 7、12%）、二级导航行（侧栏知识库，圆角 6、9%）；导航行的字重与
accent 前景色切换保留，标签短不存在抖动问题。hover 一律是 `primary` 4%，选中优先于 hover 不叠色。
收集工作区的两栏因此不用系统原生 `List(selection:)` 的实心高亮——那是这套里唯一一个和其他
tab 长得不一样的选中态，代价是失去原生的上下方向键切换（任务 / Agent / 知识三栏本来也没有）。
三栏底色也统一为「侧栏 sidebar / 列表栏 surface / 详情栏 canvas」；收集的列表栏此前是 canvas，
和详情栏同色，三栏之间只剩一根 Divider。

状态色只有 `ATMTheme` 的 `success` / `warning` / `danger` 三个（外加 `…Fill` 淡底），额度卡的
`quotaColor` 与缓存命中率复用同一组值。此前 `ATMTheme.green` 和 `orange` 都被定义成 `accentLight`
的别名，于是「警告」实际渲染成强调色蓝——搜索面板不可用时那个 ⚠️ 就是蓝的，数据健康页
`severity == "warning" ? orange : accent` 的三元两边同色形同空转——各处只好绕过主题直接写
`Color.orange` / `.green`，透明度散在 0.75–1.0 六个值。分类色（收集里的沉淀、撤销等）走
`ATMTheme.palette`，不再另开裸 `.purple` / `.indigo`。唯一的例外是刘海
（[`ATMAgentNotch.swift`](Sources/ATMMenuBarApp/ATMAgentNotch.swift)）：它是近黑底的浮层，
自带一套更亮更饱和的色值（`completionGreen` 等），套桌面窗口的状态色会糊在背景里。

字号统一由 [`ATMTypography.swift`](Sources/ATMMenuBarApp/ATMTypography.swift) 的 `ATMFont` 语义档位
提供，基准对齐 macOS 标准排版（正文 13、次要 11–12），不再散落字面量；`mono` 与同语境 sans 同档，
数字列的对齐靠 `.monospacedDigit()` 而不是缩字号。侧边栏「设置」提供跟随系统、浅色、深色三种
主题模式，以三张界面预览卡展示；系统卡同时预览浅色和深色。选择会立即应用到主窗口、菜单和菜单栏
浮层，并通过 `UserDefaults` 保留。正文字号（小 13 / 中 15 / 大 17 / 特大 20）
**只影响长文阅读区**：任务描述、任务进展、知识文档、共享记忆、Agent
会话回复。侧边栏、列表行、表格、标签等界面文字固定不可调——整个界面一起放大后“大”档过于压迫，
而这些位置是扫一眼而不是读的。改档只会重绘正文视图本身（它们各自观察 `ATMAppearance`），
不做整树重建，所以滚动位置和展开状态不会丢。

App 在启动时装载主菜单（[`ATMMainMenu.swift`](Sources/ATMMenuBarApp/ATMMainMenu.swift)）。
macOS 的 `⌘V`/`⌘C`/`⌘X`/`⌘A`/`⌘Z` 由编辑菜单项分发而不是由输入框自己处理，所以没有主菜单时
任务标题、描述、知识编辑器和搜索框都无法粘贴——菜单是这些快捷键的唯一来源，不要移除。

App 每 60 秒通过一次 `atm dashboard --json` 获取带版本号的完整只读快照，并按 5 分钟节奏执行
完整同步。协议 v1 的 JSON Schema 位于
[`docs/contracts/dashboard-v1.schema.json`](../../docs/contracts/dashboard-v1.schema.json)。
打开主窗口、快速面板或右键菜单时也会先触发一次增量同步，让用户主动查看时的 Token 用量
不必等待下一轮后台刷新。

同一次刷新里并发调用一次 `atm quota --json`。额度没有并进快照协议：Codex/Grok 来自各自日志，
外部服务可通过 `quota_providers` 提供通用多指标卡片。因此 CLI 与 App 可以继续分步升级
（快照协议是版本硬握手，版本不匹配会导致整个快照解析失败）。

所有读写操作仍由 `atm` CLI 负责，不复制 ATM 的业务规则。

## 运行

要求 macOS 13+，并确保 `atm` 已安装在常见路径。开发运行：

```bash
swift run --package-path app/macos
```

> `swift run` 以裸可执行文件运行，没有 app bundle，因此系统通知功能会自动禁用（仅打印一行日志）。
> 需要验证图标、通知、辅助功能或 UI 自动化时，运行
> `app/macos/Scripts/run-dev-app.sh`。它仍使用 Debug 构建，但会放进独立的
> `ATM Dev.app`，使用开发 bundle ID，终端日志也会保留。

如果 `atm` 不在 `/usr/local/bin`、`/opt/homebrew/bin` 或 `~/.local/bin`，可显式指定：

```bash
ATM_EXECUTABLE=/path/to/atm swift run --package-path app/macos
```

## 构建可启动 App

```bash
app/macos/Scripts/build-app.sh
open app/macos/dist/ATM.app
```

产物使用 ad-hoc 签名，适合本机使用。正式分发时应替换为 Developer ID 签名和公证流程。

## 设计来源

Agent presence 与“点击回到来源会话”的交互参考了
[Ping Island](https://github.com/erha19/ping-island)；ATM 只借鉴其产品语义与逐级路由思路，
实现仍基于自己的 transcript、进程状态和 SwiftUI 桌面信息架构。
