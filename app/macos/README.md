# ATM for macOS

ATM 的原生 macOS 桌面应用。主窗口提供任务搜索与筛选、Markdown 详情、编辑、
外部需求收集、
Agent 活跃监视器、知识工作台，以及配额与 Token/会话用量分析。用量页顶部“额度”按 Agent 展示
可用的速率限制窗口、已用百分比和重置时间。知识工作台从左侧“知识”展开具体
知识库，中栏浏览文章，右栏查看完整内容；共享记忆作为特殊知识库呈现。知识库管理列表支持拖拽或右键上移/下移，调整后的顺序会同步到文章分组并跨启动保留。工作台支持
新建与导入 Markdown、编辑信息、右键移动到其他知识库、可恢复归档及二次确认永久删除。跨任务、
会话、知识与共享记忆的搜索统一由标题栏输入框提供，`⌘K` 可直接聚焦并展开结果下拉；知识库列表本身不带库内检索。详情页支持 Markdown
编辑/预览和 `⌘S` 保存；文件导入条目会回写源文件并重新导入，共享记忆
会创建保留历史的新版本。Agent 页按“需要你、正在活跃、刚刚活跃”展示近期观察到的各个 Agent 会话，
点击卡片后在右侧显示详情，再由“打开来源”回到来源会话：Codex Desktop 使用完整 thread id 的 `codex://threads/…`
深链，Terminal/iTerm 使用进程 TTY 选择对应标签页，IDE 在缺少会话级标识时打开对应项目窗口。
Codex 会话标题直接读取其 thread index，与 Codex Desktop 中显示的标题保持一致；卡片和详情同时保留
最近一次用户输入，长回合中也会从轻量 `user_message` 事件反向定位，不受工具日志数量影响。首次定位 Terminal/iTerm
时 macOS 可能会请求“自动化”权限。默认开启的“刘海 Agent”会把活跃及最近 30 分钟的会话保留在屏幕顶部：
物理刘海屏以相机区域为中心显示两侧状态，无刘海屏降级为顶部居中的紧凑悬浮条。交互沿用 Ping Island
的原因分层：悬停后用一次连续的窗口动画直接展开到完整会话列表的最终尺寸，不叠加内容层的第二段动画；
悬停判定不走 SwiftUI 的 `.onHover`（tracking area 会在窗口变大时报一次假的移出，导致展开与收起来回翻转），
而是按光标真实位置判断，并且开合到点后都会重新读一次光标位置复核：停留 180ms 才展开、离开 220ms 才收起，
光标确实还在面板内时一律不收。紧凑态的触发区比画出来的条窄 20pt，避免伸手去点菜单栏图标时顺带把它拖开；
展开后改用完整面板范围，边缘不再是悬崖。展开态沿用 Ping Island 的浮岛信息架构：顶部只保留
Agent 配额、提示音与设置，下面用独立圆角卡片并排展示项目、当前任务、最近一轮对话、时间、Agent 和来源，
不再叠一层“会话列表”导航栏。每张卡显式标注“工作中 / 已完成 / 需要你 / 最近”；完成后的新输入会把
会话重新切回“工作中”，而“需要你”始终优先。点击紧凑态会固定同一个列表；点击外部后收起；点击会话直接回到来源。
绿色表示活跃、灰色表示最近，需要介入的新状态使用独立
通知态短暂展开；Agent 产生新的完整结果时也会短暂展开绿色完成卡，只显示会话标题和一行结果摘要，
点击直接回到来源。同一结果只提醒一次，App 启动时不会补播历史完成项，会话短暂离线再出现也不会重播；
“需要你”提醒优先于完成提醒。没有活跃或最近会话时自动隐藏。设置 → 刘海可开关，并沿用 Ping Island
的自定义能力再提供四项：显示屏（自动 / 主屏 / 指定某块外接屏，指定屏拔掉后自动回退到“自动”）、
无刘海屏位置（顶部居中 / 靠左 / 靠右，物理刘海屏始终居中对齐相机区域）、最近会话保留（15 / 30 / 60 分钟
或一直保留，“需要你”不受此限）、通知停留（4 / 8 / 15 秒或手动收起）。
同一页的“Agent 提示音”按“开始处理、需要介入、处理完成”分别选择声音并支持预听和音量；默认采用
Ping Island 的 `Menu Select`、`Approval Alert`、`Submit Blip` 三段 8-bit 音效，同时保留 macOS 系统音选项。
默认只开启需要介入与处理完成。声音由状态转移触发并按结果去重，不会随 3 秒轮询重复播放。
同一页的“Agent 事件推送”把感知层从扫会话记录换成 hook 推送：装上后 Agent 卡在授权或等你输入的那一刻
会经 `~/.atm/notch.sock` 直接推给刘海，刘海显示的是 Agent 报上来的原因（等待授权、等待输入）和被卡住的
工具名，而不是从最后一句回复里猜的。扫记录看不到工具授权——那一刻 Agent 不写任何文字——所以这不只是
更快，是原本完全漏掉的信号。装的都是只上报的 hook，不会拦住工具调用；App 没在跑时 hook 立刻静默退出。
已接 hook 的会话由事件驱动播放提示音并即时刷新，轮询退到 8 秒兜底；没接 hook 的 Agent 行为不变。
刘海或 Agent 工作区可见时会独立每 3 秒刷新一次
轻量会话状态，避免受主面板 60 秒刷新周期影响；较慢的主面板响应不会覆盖更新的实时状态。详情页只保留
当前输入、最新完成结果、关联任务与技术信息在「概览」页签，执行动态单独一个页签（默认展开最近十条）；
“查看完整动态”会打开弹窗，并在「执行动态」和「完整对话」两个页签间切换。「全部日志」页签和「中断」按钮
只在这个会话**本身就是**某次 ATM 派发时出现——判定要求 run 记录的 session id 与该会话匹配，或者用户正是从那个
Todo 的“Codex 执行”卡片跳过来的；仅仅“绑定了同一个 Todo”不算（否则你自己在别的 Agent 里做同一个任务，
会看到别人的原始日志、按下的“中断”也会停掉别人的进程）。原始日志按最近 1 MB 读取，CLI 截断时会自带
`[... earlier log truncated ...]` 前缀。没有实时活动的 Session binding 不计入
活跃 Agent，Codex Desktop 内部的 auto-review helper 也不会伪装成用户可返回的活跃会话。菜单栏快速面板
只保留工作中、等待中、需处理项、活跃 Agent 和常用操作。回到 ATM 不必先去菜单栏找那个小图标：默认
`⌥⌘A` 是一个系统级快捷键，在任何应用里按一次唤起主窗口、再按一次收起——按键唤出的窗口也得能用按键送走。
收起只在 ATM 已经在前台且主窗口就是当前窗口时发生，否则同一下按键是“把它拿到前面来”，不会把一个看不见的
窗口悄悄藏起来。唤起时保留上次停在的页签，因为这个快捷键的意思是“回到我刚才在做的事”（状态栏右键的
“打开 ATM 主窗口”仍固定回到任务）。设置 → 通用 → 全局快捷键可以关掉它、按下新组合改绑，或把呼出目标
从主窗口切成快速面板；组合至少要含 ⌘、⌃ 或 ⌥，否则会跟普通打字抢键。注册走 Carbon 的热键表而不是键盘
事件监听：后者需要“输入监控”权限，而且只能旁观、拦不住按键，被呼出的同时前台应用也收到了这一下。别的
应用已经占着同一个组合时注册会失败，那一行设置会当场说明这个组合已被占用，而不是留下一个按不动的快捷键。临时记一条任务有三个入口：面板底部的
“添加任务”、`⌘N`、以及状态栏图标右键菜单（面板没展开时也能用）。`⌘N` 由主菜单“文件 → 新建任务”
持有而不是挂在“任务”页那个“新建”按钮上：输入卡本来就覆盖整个窗口，快捷键跟着页签消失的话，
人在“收集”或“知识”里想记一条得先切回任务页。菜单键等价在任何页签和快速面板上都成立，弹卡时
留在当前页签（提交后才跳到新建的任务上；状态栏右键的“添加任务”仍固定回到任务页）。`⌘S` 保存和
`⌘K` 搜索仍归标题栏输入框，它本来就不因页签而消失。三个入口都激活主窗口
并弹出同一张输入卡——300pt 的面板放不下项目和优先级两个 chip，维护两套 composer 只会让它们
逐渐不一致，所以菜单栏只提供入口，不复制输入界面。提交后弹窗收起并选中新建的任务。
任务详情和任务行右键都能“复制启动
提示”，把一行指针放进剪贴板；粘贴进新的 Codex 会话后 AI 会自己去读任务文档。完成任务后会
发送 macOS 原生通知，点击通知可打开主窗口。
任务详情的“Agent Sessions”页签把每个绑定会话按主题列出，而不是只列 id：标题由 CLI 决定——先用
Agent 自己写进索引的会话标题，Codex 不写标题就读它的 thread index，都没有才退回该会话第一句真正
由人打出来的提问（插件清单、AGENTS.md 之类的注入前言会被跳过）。行内还给出绑定时间、会话历时、
提问与工具调用次数、花费和工作目录。页签里只有这一份绑定历史，所以不再套一层带标题的白色卡片。
行本身不可点，两个动作都在行尾：一个弹出完整对话（`atm session show`），另一个回到来源
会话——会话还活着就精确聚焦它的终端，已经结束的 Codex 线程用 `codex://threads/…` 深链重新打开，
其余已结束会话不显示回到来源的按钮，只能看记录；从未被索引的会话没有对话可看，查看按钮置灰。
悬停高亮覆盖整行，包含行尾按钮。完整对话用 AppKit 文本视图渲染，只排版视口内的内容，
几万字的会话也不卡，并且支持 ⌘F 查找和跨全文选择。

“收集”工作区采用来源、处理记录、详情三栏布局。来源管理列表支持拖拽或右键上移/下移，调整后的顺序会同步到处理记录分组并跨启动保留。顶部的齿轮入口集中控制自动收集、后台检查频率并展示
分类模型和连接器健康；来源开关、处理规则和连接器错误留在对应来源详情中，设置页不再重复维护一份。
添加来源时填写 `collection_connectors` 中配置的连接器、来源类型和稳定 ID；连接器支持发现能力时，弹窗通过 typed IPC 搜索并列出候选。来源右键“查看消息记录”、
或处理记录详情“来源”卡片里的同名入口，会读最近 50 条聊天原文，用来补齐 `raw_context` 之外的上下文。
来源可选择高频“任务提取”或低频“收集结论”；后者在配置层被限制为只能形成结论或忽略，永不创建 Todo，
模型判成建任务也会被降级成结论。结论先留在收集详情，用户明确保存后才写入来源配置的知识库集合。
“任务提取”来源还可显式开启“新 Todo 自动交给 Codex”（默认关闭）；派发使用受保护执行策略，失败证据保留在
处理记录，任务详情可查看实时状态并重试。委派关联到 Agent 会话后，详情页可直接“回到会话”；输入、授权和
其他交互控制继续由原生 Agent 提供，ATM 只保留任务状态、执行证据和日志。已有执行可填写新的修改要求，
恢复同一个 Codex 线程继续处理，每轮仍保留独立执行记录。成功只进入“待验收”，不会自动标记完成。
弹窗分两段：先通过 `collect.history` typed IPC 从本地已同步的记录读取，再调用同一 use case 的在线模式以连接器结果替换并同步进本地库（默认保留 90 天，公开 CLI 的 `atm collect search` 仍可检索）；
读取中副标题写“正在读取最新…”，连接器不可用时转成橙色说明这批是本地记录，而不是当成最新状态。App 常驻期间即使主窗口关闭，也只定时调用 `collect.run` typed IPC；知识保存始终由用户触发。
新 Todo、Todo 补充和新结论会分别以来源、类型和具体标题发出原生通知，点击直接定位对应处理记录；持久未读数
显示在侧栏与菜单栏，打开对应记录即标为已读，也可右键改回未读或一键“全部已读”。失败仍单独提示具体来源和错误。处理记录支持查看原始聊天、打开
Todo、重新处理、转成 Todo、修正元数据、保留审计的撤销，以及可恢复的「了结记录」；了结后进入
「已保存与已了结」，不改关联 Todo，也不会像删除那样让消息在下一轮重新出现，可从该组「重新打开」。
历史补充记录仍可查看和撤销。
失败分两处呈现：采集失败能归到某个来源，写在该来源右栏的“采集状态”卡片里；添加/删除来源、修正、撤销这类没有来源可挂的失败
走中栏顶部的内联提示——两处不重复同一句话，但也不能让任何一类失败没有落点。
同一 Todo 的补充记录收进新建主记录的详情，不再和新建平铺；没有对应新建记录的历史补充仍单独显示。
中栏三种分组（来源、“其他来源”、“已保存与已了结”）标题右侧的省略号菜单都有“清空记录”，删掉的是这一组当前
列出的记录，来源配置和记录写出的 Todo 都保留——所以来源菜单里的两条销毁动作分别叫“清空记录”和“删除来源”。
确认框会说明有多少条、其中几条的 Todo 保留；一整组走一次 `collect.item.delete` typed IPC，Collector
service 在一个事务中删除，不会出现半清空的分组，并再次校验 `confirmed=true`。

列表行与导航行的选中/悬停表面统一由 [`ATMListRow.swift`](Sources/ATMMenuBarApp/ATMListRow.swift)
的 `atmRowSurface` 提供，行内容仍归各自的视图。规则是**只填充，不描边、也不在选中时切字重**：
两者都会让行内文字重排——描边挤掉一圈可用宽度，字重切换改变字形宽度——点一下行标题就会左右抖一下。
同一原语分三档：中栏内容行（任务 / Agent / 知识 / 收集记录 / ⌘K 搜索结果，圆角 8、accent 11%）、
导航行（侧栏分区、收集来源，圆角 7、12%）、二级导航行（侧栏知识库，圆角 6、9%）；导航行的字重与
accent 前景色切换保留，标签短不存在抖动问题。hover 一律是 `primary` 4%，选中优先于 hover 不叠色。
收集工作区的两栏因此不用系统原生 `List(selection:)` 的实心高亮——那是这套里唯一一个和其他
tab 长得不一样的选中态，代价是失去原生的上下方向键切换（任务 / Agent / 知识三栏本来也没有）。
三栏底色也统一为「导航 rail / 列表栏 listPane / 详情栏 canvas」；收集的列表栏此前是 canvas，
和详情栏同色，三栏之间只剩一根 Divider。

右侧详情区保留“固定头部 + 分割线 + 正文”的两段结构；任务、收集、Agent、知识、设置、用量和 AI Day
只把分割线下方的正文放进一张带圆角的主卡片，头部不进卡片。正文内部按留白与分隔线组织段落，不再为
每组字段重复套卡片；额度指标、告警等本身就是独立对象的内容仍保留必要的独立表面。
有页面切换时，固定顺序为「标题与操作区 → 分割线 → Tab → 正文卡片」；Tab 不塞进头部，
也不放进正文卡片。
标题与 Tab 固定在顶部；它们下方的画布负责滚动。正文卡片是滚动内容的一部分，高度跟随正文，
不再撑满剩余空间后让卡片内部单独滚动；仅文本编辑器和原始日志保留自身需要的最小阅读高度。

状态色只有 `ATMTheme` 的 `success` / `warning` / `danger` 三个（外加 `…Fill` 淡底），额度卡的
`quotaColor` 与缓存命中率复用同一组值。此前 `ATMTheme.green` 和 `orange` 都被定义成 `accentLight`
的别名，于是「警告」实际渲染成强调色蓝——搜索面板不可用时那个 ⚠️ 就是蓝的，数据健康页
`severity == "warning" ? orange : accent` 的三元两边同色形同空转——各处只好绕过主题直接写
`Color.orange` / `.green`，透明度散在 0.75–1.0 六个值。分类色（收集里的沉淀、撤销等）走
`ATMTheme.palette`，不再另开裸 `.purple` / `.indigo`。唯一的例外是刘海
（[`ATMAgentNotch.swift`](Sources/ATMMenuBarApp/ATMAgentNotch.swift)）：它是近黑底的浮层，
自带一套更亮更饱和的色值（`completionGreen` 等），套桌面窗口的状态色会糊在背景里。

字号统一由 [`ATMTypography.swift`](Sources/ATMMenuBarApp/ATMTypography.swift) 的 `ATMFont` 语义档位
提供，基准对齐 macOS 标准排版（正文 13、次要 11–12），不再散落字面量；`mono` 与同语境 sans 同档，
数字列的对齐靠 `.monospacedDigit()` 而不是缩字号。侧边栏「设置」提供跟随系统、浅色、深色三种
主题模式，以三张界面预览卡展示；系统卡同时预览浅色和深色。选择会立即应用到主窗口、菜单和菜单栏
浮层，并通过 `UserDefaults` 保留。正文字号（小 13 / 中 15 / 大 17 / 特大 20）
**只影响长文阅读区**：任务描述、任务进展、知识文档、共享记忆、Agent
会话回复。侧边栏、列表行、表格、标签等界面文字固定不可调——整个界面一起放大后“大”档过于压迫，
而这些位置是扫一眼而不是读的。改档只会重绘正文视图本身（它们各自观察 `ATMAppearance`），
不做整树重建，所以滚动位置和展开状态不会丢。

按住 `⌥Space` 说话、松手把文字写进当前光标处——语音输入是唯一一个不看 ATM 也在用的功能，所以它
不在任何页签里，只是一个系统级快捷键。按住而不是按一下切换：口述的边界就是手指的边界，说完松手比
「再按一次结束」少一个要记的状态，也不会留下一个忘了关的录音。松手前按 `⎋` 整段作废，什么都不写。
录音期间屏幕底部居中出现一条浮层，它是 `.nonactivatingPanel` 且用 `orderFrontRegardless()` 呈现——
一旦激活 ATM 就抢走了目标应用的焦点，那一下粘贴会落在 ATM 自己身上。
快捷键复用了呼出主窗口那套 Carbon 热键表（[`ATMGlobalHotKey.swift`](Sources/ATMMenuBarApp/ATMGlobalHotKey.swift)），
但多注册了一条 `kEventHotKeyReleased`：拿到「松手」这个事件是按住说话能成立的前提，否则就得去监听
键盘，而那需要「输入监控」权限。同一张表里现在有三个 id——呼出主窗口、语音输入，以及录音期间临时
占用的裸 `⎋`。`⎋` 不走偏好也不过 `ATMHotKey.isValid` 那道「至少要有一个 ⌘/⌃/⌥」的检查：那道检查是
为了不跟普通打字抢键，只对人能绑的快捷键成立，而「按 ⎋ 取消」必须在第一次使用、权限对话框还开着的
时候就是真的——换成 `NSEvent` 全局监听就得先有辅助功能权限，恰好在最需要它的那一刻是假的。
Carbon 的松手事件在「先松 ⌥ 再松 Space」这类按键顺序下有丢失的报告，所以录音期间每 120ms 读一次
`NSEvent.modifierFlags`（静态属性，读它不要任何权限）复核按键是否还按着，另有 60 秒硬上限；两者都
只是兜底，正常路径仍是松手事件本身。

识别有两个引擎，边界是 `ATMSpeechTranscribing` 一个协议，热键、浮层、写入三层都不知道是谁在转写。
默认 SenseVoice Small：本地 int8 模型，音频不出这台机器，中文和中英混说明显更准。它的模型是 160MB
的下载，所以不随 App 走，没下载时自动回落 Apple Speech——设置里能看到模型状态、浮层会写出实际用的
引擎名，所以回落是可见的，而不是静默的。两个引擎有一处差别会走到屏幕上：Apple Speech 边说边给
partial 文本，SenseVoice 是离线批量识别，说完才有结果，那种情况下浮层显示的是从音频算出来的真实
RMS 电平条。用真电平而不是一段装饰动画，是因为动画只能说明「在录」，而电平顺带回答了「这个麦克风
到底有没有收到我」——选错输入设备是口述悄悄什么都没录到的最常见原因，平的电平一眼能看出来。
SenseVoice 的模型不在启动时预加载：推理只发生在松手那一刻，模型加载可以和人说话并发跑，说超过一秒
加载就完全被藏住了，换来的是常驻菜单栏的进程不用一直背着约 300MB 的 onnxruntime 会话；空闲五分钟
自动卸载，一阵一阵的连续口述期间一直是热的。

转写完成后只做本地处理，不过 AI：清掉 SenseVoice 写在文本里的 `<|zh|>` 之类标记，归一空白，套用设置里
的替换词典，去掉标点前那个空格（混说时识别器留下的那个空格是「这是口述的」最明显的痕迹），可选去掉
句尾句号——口述多半落在聊天框、提交信息、提示词里，那个句号每次都要手删一下，只去一个所以
「等一下。。。」保持原样。这几步的顺序是有依赖的，去标记会留下双空格、替换词可能引入新空格，所以
清空白和收标点必须排在它们后面。这段逻辑全部在
[`ATMVoiceTextCleanup.swift`](Sources/ATMMenuBarApp/ATMVoiceTextCleanup.swift) 里，不碰 AppKit、
不碰 UserDefaults、不碰音频，因为让口述读起来别扭的从来不是识别器而是字符串。

写入走剪贴板加一次模拟 `⌘V`，而不是辅助功能的 `AXUIElementSetAttributeValue`：直接设值会替换掉输入框
里已有的内容，在终端和 Electron 窗口里根本不生效，而粘贴去的地方就是打字会去的地方。剪贴板是借的，
贴完还原，但只在期间没有别人写过才还原——处理粘贴时自己往剪贴板写东西的应用，现在才是它的主人。
模拟按键需要辅助功能权限，没有时不算失败而是降级：文字留在剪贴板上，浮层写「缺少辅助功能权限，
按 ⌘V 贴上」，并且刻意不还原剪贴板快照——那一刻剪贴板是刚说的那段话的唯一副本。这条降级路径不是
可选的：产物是 ad-hoc 签名，每次重新构建代码标识都会变，已授权的辅助功能条目随之失效，所以「权限
突然没了」在开发期是常态。检查权限用的是不带提示参数的 `AXIsProcessTrusted()`——带提示的那个会弹一
个抢焦点的模态框，正好把要粘贴进去的应用挤到后面；申请权限的入口放在设置里，那里打断人是没关系的。

设置 → 语音管快捷键、引擎与模型下载、识别语言（一个选择同时映射 Apple 的 `Locale` 和 SenseVoice 的
语言码，避免两个引擎对「中文」的理解各走各的）、Apple Speech 的「仅使用本地识别」、替换词典和句尾
句号，末尾列出麦克风 / 语音识别 / 辅助功能三项权限的当前状态——「口述没反应」在这三者之间是无法区分的。
最后保留上一次转写结果和一个复制按钮：粘贴失败时它是唯一的救回途径。

App 在启动时装载主菜单（[`ATMMainMenu.swift`](Sources/ATMMenuBarApp/ATMMainMenu.swift)）。
macOS 的 `⌘V`/`⌘C`/`⌘X`/`⌘A`/`⌘Z` 由编辑菜单项分发而不是由输入框自己处理，所以没有主菜单时
任务标题、描述、知识编辑器和搜索框都无法粘贴——菜单是这些快捷键的唯一来源，不要移除。

App 每 60 秒通过一次 `_ipc dashboard.snapshot` 获取带版本号的完整只读快照，并按 5 分钟节奏执行
完整同步。请求通过 JSON stdin 传 section 与可选 Session ID；协议的 JSON Schema 位于
[`docs/contracts/dashboard-v1.schema.json`](../../docs/contracts/dashboard-v1.schema.json)。
打开主窗口、快速面板或右键菜单时也会先触发一次增量同步，让用户主动查看时的 Token 用量
不必等待下一轮后台刷新。

同一次刷新里并发调用一次 `atm quota --json`。额度没有并进快照协议：Codex/Grok 来自各自日志，
外部服务可通过 `quota_providers` 提供通用多指标卡片。因此 CLI 与 App 可以继续分步升级
（快照协议是版本硬握手，版本不匹配会导致整个快照解析失败）。

所有读写操作仍由 `atm` CLI 负责，不复制 ATM 的业务规则。

## 运行

要求 macOS 13.4+，并确保 `atm` 已安装在常见路径。开发运行：

```bash
swift run --package-path app/macos
```

> 下限是 13.4 而不是 13.0，因为语音识别依赖的 `sherpa-onnx-spm` 提供的是按 13.4 编译的预建
> onnxruntime 切片：链进 13.0 的 target 合法，但每次链接会刷约 690 条
> “built for newer macOS version” 警告，把所有值得看的警告全埋掉。13.4 发布于 2023 年 5 月，
> 下限只挪了几周。
>
> 首次构建会拉约 89MB 的 xcframework。里面是静态库（上游把 onnxruntime 合进了
> `libsherpa-onnx.a`），所以直接静态链进可执行文件，`Scripts/build-app.sh` 不需要额外拷
> `Contents/Frameworks` 或改 rpath；代价是产物体积明显变大。

> `swift run` 以裸可执行文件运行，没有 app bundle，因此系统通知功能会自动禁用（仅打印一行日志），
> **语音输入也用不了**：可执行文件本身是 ad-hoc 签名的、Info.plist 也链进了
> `__TEXT,__info_plist`，但进程不是 bundle、没注册进 Launch Services，TCC 的麦克风授权框因此
> 弹不出来，而那个请求的回调也就永远不来。按下语音快捷键会直接告诉你这件事并让你换运行方式，
> 而不是停在「正在打开麦克风…」上等；设置 → 语音的权限区同样会横幅提示。
> 需要验证图标、通知、语音输入、辅助功能或 UI 自动化时，运行
> `app/macos/Scripts/run-dev-app.sh`。它仍使用 Debug 构建，但会放进独立的
> `ATM Dev.app`，使用开发 bundle ID，终端日志也会保留。

如果 `atm` 不在 `/usr/local/bin`、`/opt/homebrew/bin` 或 `~/.local/bin`，可显式指定：

```bash
ATM_EXECUTABLE=/path/to/atm swift run --package-path app/macos
```

## 构建可启动 App

```bash
app/macos/Scripts/build-app.sh
open app/macos/dist/ATM.app
```

产物使用 ad-hoc 签名，适合本机使用。正式分发时应替换为 Developer ID 签名和公证流程。
